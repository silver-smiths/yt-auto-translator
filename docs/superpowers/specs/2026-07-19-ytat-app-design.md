# YTAT 앱 전환 설계 (차기 버전) — YouTube 자막·메타데이터 번역 크로스플랫폼 앱

작성일: 2026-07-19
상태: 설계 초안 (스펙 검토 게이트 대기)

## 1. 목표
- **데스크톱·크롬·익스텐션** 3중 한계를 벗어나 **크로스플랫폼 모바일 앱**으로 전환
- 검증된 **유튜브 자막-트랙 번역 모델**을 그대로 유지, 기존 백엔드 재사용
- **앱 광고 수익화** 확대 (회사의 핵심 사업 강점)
- 틱톡/릴스는 그쪽이 자막 트랙 API를 열면 확장 (현재 API 부재 → 보류)

## 2. Non-goals (이번 범위 아님)
- 틱톡/릴스 번인(자막 굽기)·ASR(음성인식) 파이프라인 — Phase 3 조건부
- 영상 편집/생성 기능
- 익스텐션 즉시 폐기 (당분간 병행 유지 가능)

## 3. 스택 & 아키텍처
- **클라이언트**: React Native + Expo + TypeScript (iOS+Android 단일 코드, iOS 우선 광내기)
- **백엔드**: 기존 Cloudflare Workers(Hono) + Supabase — REST API 그대로 재사용
- **인증**: expo-auth-session (Google OAuth, scope: `youtube.force-ssl` + email)
- **광고**: Google AdMob (react-native-google-mobile-ads)

## 4. 재사용 맵 (익스텐션 → 앱)
| 기존(익스텐션) | 앱 |
|---|---|
| 백엔드 API(크레딧·번역·결제·공지·추천) | **그대로** |
| YouTube Data API 업로드/조회 로직 | 로직 포팅 (JS→TS) |
| chrome.identity OAuth | expo-auth-session |
| content-script 사이드바 UI | 네이티브 화면 재작성 (신규) |
| chrome.storage | expo SecureStore / AsyncStorage |
| i18n(chrome.i18n) | i18next 등 |
| 결제 웹페이지(KakaoPay/PayPal) | ⚠️ IAP 검토 필요 (6-a) |

## 5. 핵심 데이터 흐름
1. 구글 로그인(OAuth) → 백엔드 세션 교환
2. 내 유튜브 영상 목록 조회 (YouTube Data API)
3. 영상 선택 → 대상 언어 선택 → 번역 시작
4. 백엔드가 자막/제목/설명 번역(Gemini) → YouTube Data API로 트랙 업로드
5. 크레딧 차감(실패 무과금) → 이력·공지 표시

→ 익스텐션과 동일하되 "Studio 페이지 주입"이 사라지고 **앱이 직접 API 호출**.

## 6. 핵심 결정 & 리스크

### 6-a. ⚠️ 앱스토어 결제(IAP) — 최대 리스크
- 크레딧 = 디지털 재화 → Apple/Google 원칙상 **IAP 강제**(수수료 15~30%). 현재 외부결제(KakaoPay/PayPal)를 앱에서 그대로 쓸 수 없음.
- 한국: 전기통신사업법으로 외부결제 허용되나 Apple **External Purchase Entitlement + 한국 전용 바이너리** 필요, 그래도 ~26% 수수료.
- **권장 전략** (수익 모델 재편):
  - 무료 이용 + **리워드 광고로 크레딧 적립**을 1차 수익축으로 (광고수익 = 스토어 수수료 없음, 회사 강점)
  - 직접 구매는 **IAP**(소규모 사업자 프로그램 15%)로 스토어 준수
  - 웹 충전(수수료 0)은 "가입·충전은 웹에서" 리더앱 방식 검토 (정책 리스크 있음 — 법무·스토어정책 확인 필요)
- → 오히려 **광고 중심 수익 모델**로 재편되어 회사 강점과 정합.

### 6-b. OAuth (모바일)
- `youtube.force-ssl`은 제한 범위 → Google OAuth 앱 검증 필요 (익스텐션으로 이미 검증됐다면 재활용). 모바일용 클라이언트 ID 별도 발급.

### 6-c. 광고 수익화 (AdMob)
- 무료 구간 배너/전면 + **리워드 광고 → 크레딧 적립**으로 자연스러운 수익.

## 7. 수익화 설계 (재편)
- **무료**: 광고 노출 + 리워드 광고로 소량 크레딧 적립 → 라이트 유저 유입
- **유료**: IAP로 크레딧 구매(헤비 유저) — 스토어 준수
- 광고 수익 = 회사가 가장 잘하는 것 + 스토어 수수료 없음 → 마진 방어

## 8. MVP 단계
- **Phase 1 (MVP)**: RN+Expo 앱, 구글 로그인, 영상 목록, 자막+제목+설명 번역, 진행률, 이력, 공지. 결제는 IAP 최소 구현. **iOS 우선**.
- **Phase 2**: AdMob(배너+리워드→크레딧), 추천, 다국어 UI 완성.
- **Phase 3 (조건부)**: 틱톡/릴스가 자막 트랙 API 제공 시 확장, 또는 번인(ASR+렌더) 별도 하위 프로젝트로 분해.

## 9. 테스트 전략
- 로직(API 클라이언트·번역 오케스트레이션): 유닛 테스트(Jest)
- OAuth·업로드: 실제 유튜브 테스트 채널로 E2E
- 결제(IAP): 스토어 샌드박스
- iOS/Android 양쪽 디바이스 스모크 테스트

## 10. 미해결 질문 (스펙 확정 전 결정 필요)
1. 수익 모델 최종 비중: IAP vs 웹충전 vs 리워드광고
2. 익스텐션 계속 유지 vs 단계적 종료
3. 한국 전용 바이너리(외부결제 ~26%) 감수 여부
4. 앱 이름/브랜딩(스토어 등록명)
