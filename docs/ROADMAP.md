**목적**: 특정 언어(예: zh-TW)만 실패 급증 시 전체 자막 중단 대신 그 언어만 `lang.disabled`에 자동 추가.
**해야 하는 것**
- [ ] `runAutoHeal`에서 feature=subtitles 내부를 `lang`별로 재집계
- [ ] 언어별 임계 초과 시 `lang.disabled` 배열에 append(중복 방지) + 텔레그램 + `ops_actions` 기록
- [ ] 익스텐션은 이미 `lang.disabled` 존중하므로 클라이언트 변경 불필요
- **위치**: `backend/src/routes/ops.js` `runAutoHeal()`
- **주의**: 이미 error 태깅에 `lang` 포함됨(자막 실패 요약은 언어 미분리 — 언어별 실패 태깅 보강 필요)

## ③ Phase 3 — AI 수정 루프 (사람 게이트)
**목적**: 신규 오류 지문 → AI가 원인 코드 추적 → 수정안+테스트 → PR 생성. 머지·배포는 사람.
**해야 하는 것**
- [ ] 스케줄드 실행(cron/routine)으로 `incidents` status='open' 신규 지문 조회
- [ ] 오류 지문/스택 → 코드 위치 매핑 → 수정안 작성 → 테스트 실행 → **PR 생성**(자동 머지 금지)
- [ ] **가드레일(필수)**: 결제·크레딧·인증·보안·DB 마이그레이션 관련은 **자동 수정 금지, 사람 검토 강제**
- [ ] 백엔드 수정은 카나리 제안까지, 익스텐션 수정은 PR+버전범프까지(스토어 제출 수동)
- **선행**: 배포 후 실제 오류 데이터가 쌓여야 의미 있음

## 참고 — 자가수복 루프 현재 상태 (완성분)
```
오류 → /ops/errors 저장·지문·텔레그램[P0] → cron 5분 runAutoHeal 자동 OFF[P2]
     → 익스텐션 GET /ops/config 1분 폴링 → 기능 중단+배너[P1] → (사람)수정·배포·재활성
```
- 못 하는 핵심: **자동 코드 수정·배포(③)**, **검증·대시보드(④)**. 익스텐션 자체 즉시수정은 스토어 심사 때문에 구조적으로 불가(→ 서버 스위치로 우회).
